```sh
node scripts/run-w06-table-invitation-browser.mjs
```

Result: **1 Playwright test passed in 14.3 seconds.** The runner confirmed the local Supabase project, API/database/Mailpit ports, configured credentials, required migration/RPC, and app port before fixture creation. The captured synthetic Table is titled “Friday Dinner in Inman Park” and is dated December 11, 2026.

## Verified behavior

- An admin signs in using a real intercepted magic-link email, sees a failed delivery and expanded attempt history, and queues a retry.
- The worker sends the durable invitation to the trusted synthetic recipient through local Mailpit. The member-facing email contains a separate sign-in continuation; it does not contain an Auth token or callback link.
- The admin sees provider acceptance and attempt 2. The member follows the invitation link, requests a real magic link, completes the callback, and lands on the invitation detail.
- Member invitation detail is owner-scoped: a different admitted member receives HTTP 404 and an invitation-not-found page.
- Request history keeps the Seat request pending while presenting the Table invitation as a separate active offer. Withdrawal is unavailable while that offer is active.
- Member and admin DTO/UI checks found no recipient email, provider message ID, venue ID, or private host notes in the exposed response or member page.
- The runner cleaned its synthetic Auth, admission, profile, supply Table, request, proposal, invitation, outbox, attempt and audit rows, plus exact run-owned Mailpit message IDs. It reported cleanup complete.

No migration or database reset was run. No hosted Supabase, external mail provider, live data, payment provider or real recipient was used. The local Table-invitation worker was run once after the one-item queue guard passed.
